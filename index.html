Systems that run on their own

Five pieces of the Nava Store & NavaTek automation stack. Pick one to see the problem, the mechanism, and what changed.

Customers type in bursts. The bot answers once.

A three-stage multi-agent assistant on Zalo OA that quotes real prices from the database, routes VAT and warranty, and steps aside the moment a human joins.

  1. Zalo webhook
  2. Dedupe
  3. Lock + JSONB buffer
  4. Grace wait
  5. Merge text
  6. Classify intent
  7. Agent A · B · C
  8. Reply or hand off
Problem
Webhooks fire per message. Four short texts meant four parallel runs, four LLM bills, and answers that talked over each other.
Mechanism
A PostgreSQL row is the distributed lock. Messages that arrive while it is held go into a JSONB buffer, merge after a quiet period, and reach the model once. Agent A finds the need, B quotes from live DB tools, C closes the order. A [STAGE:x] marker moves the conversation between them.
Outcome
About 60% fewer tokens, no overlapping replies, 500+ messages a day. Staff replies are detected and mute the bot instantly.
  • n8n
  • PostgreSQL
  • Gemini Pro/Flash
  • Gemini Vision
  • LangChain
  • Zalo OA
  • Lark

One order, one alert. Even when the webhook fires three times.

Orders from Shopee, TikTok Shop, Lazada and the web storefront land in one event-driven router that tells the warehouse what to pack and when.

  1. Sapo webhook
  2. Express order?
  3. INSERT … ON CONFLICT
  4. Working hours?
  5. Lark card now
  6. Or night queue
  7. 08:00 digest
Problem
Providers retry webhooks, delete them without warning, and an order can turn into an express order after the first alert went out.
Mechanism
ON CONFLICT DO NOTHING RETURNING makes alerts idempotent at the database. The Lark card id is stored, so a normal order that becomes express is edited in place into a red alert instead of spawning a second message. Every 6 hours the workflow audits Sapo webhooks and re-registers missing ones; every 10 minutes it reconciles web orders against the ERP.
Outcome
Zero duplicate notifications, orders that fail to reach the ERP are flagged within minutes, and night orders arrive as one 08:00 digest instead of waking anyone.
  • n8n
  • PostgreSQL
  • Sapo GO / Web
  • Shopee
  • TikTok Shop
  • Lark cards

The bot never sees an empty table.

Sales edit prices in Google Sheets all day. The chatbot reads them from PostgreSQL. Between the two sits a Blue/Green swap.

  1. Read 8 sheets
  2. Normalise + slug
  3. Load stage tables
  4. Assert rows > 0
  5. Atomic swap
  6. Live, 0 s gap
Problem
DELETE then INSERT on the live table leaves a window where a failed sheet read means an empty catalogue and a chatbot that lies.
Mechanism
Data loads into products_stage and lap_may_stage. An assertion raises an exception if a stage table is empty, which rolls the transaction back. Only then do the tables swap atomically.
Outcome
8 catalogs sync every 2.5 hours with integrity checks, and the chatbot's data is never partial.
  • PostgreSQL
  • PL/pgSQL
  • Google Sheets
  • n8n

A cron server that wakes itself up and catches up.

Four times a day a Dockerised chain moves data from Sapo to Google Sheets, Zalo and Shopee. If the machine slept or the clock drifted, it notices and runs what it missed.

  1. Ofelia cron
  2. Sapo export
  3. Google Sheets
  4. Price calc
  5. Zalo sheets
  6. Shopee sync
  7. Push to backup host
Problem
Cron in Docker only runs when Docker is up, and Docker only runs when someone is logged in. WSL clocks drift while a machine idles and jobs fire late.
Mechanism
Auto-login, active hours and sleep schedules keep the host awake. A WSL time-sync task runs every 15 minutes. A catch-up script re-triggers missed jobs. A failed step stops the chain but still ships finished files. OliveTin gives staff a one-click dashboard; Cloudflare Tunnel exposes internal tools safely.
Outcome
A 4x/day chain that heals itself and that non-engineers can trigger from a browser.
  • Docker
  • Ofelia
  • OliveTin
  • Cloudflare Tunnel
  • Playwright
  • Sapo API

An internal assistant that cannot leak what you may not read.

An Obsidian-style knowledge base with a RAG assistant. Answers cite their sources, and permissions are enforced before retrieval, not after.

  1. Expand query (6 turns)
  2. Vector 1024-d
  3. Full-text unaccent
  4. RRF merge
  5. bge-reranker top 6
  6. Cited answer
Problem
Hybrid search finds the right document, including ones the asker must never see.
Mechanism
Folder RBAC and ACL on PostgreSQL ltree with inheritance, DENY-first, personal rules over department rules. Restricted documents vanish from the tree and from retrieval. Clicking a citation opens the source with the cited passage highlighted.
Outcome
One assistant for the whole company where access control is a property of the data, not of the prompt.

  • PostgreSQL
  • ltree
  • Next.js
  • bge-reranker-v2-m3
